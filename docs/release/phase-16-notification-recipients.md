# 第十六阶段：通知接收地址与最终前端门禁

日期：2026-10-23

## 变更日志

- 部门接收人对接真实 recipient_depts；自定义接收人采用 recipient_addresses，每个地址明确渠道、地址和可选名称。提供增加、移除与窄屏纵向编辑，保留编辑、复制及取消时的数据边界
- ID 按正整数字符串校验，不经 Number 舍入，不接受指数或零；邮箱和飞书地址按当前 Go 合同验证，地址渠道必须包含在配置的通知渠道中。错误原位显示，保存处理中阻止重复提交和取消
- 新建默认禁用且始终提交 status；复制保留原状态供审阅，修复原先省略 status 导致后端自动启用的问题。保留零次重试，允许明确清空描述和主题，不把未提供默认值当成显式 0
- 1.0 仅开放已实现的立即触发，不向写接口透传历史定时、间隔或条件参数。历史高级规则明确提示未支持，可保持原规则并禁用；转换立即触发须用户明确选择。历史不支持渠道同样须明确移除，不静默丢弃
- API 写入类型限定立即触发，保留历史读取字段；编辑弹窗增加代际校验，取消或重开后迟到请求不修改新表单

## 验证

新增十五项真实 Antd 组件回归，六项最初基线缺陷、三项高级触发缺陷先复现失败，再通过实现修复；覆盖部门 ID、自定义地址 round-trip、取消隔离、空地址和渠道不匹配拒绝、复制禁用状态、重复保存、历史触发禁用保留及无效 ID。与原通知十项、实例十四项一并通过

冻结源码通过：80 个测试文件 / 627 项单元测试、应用 TypeScript、11 项生产构建和布局清单检查。真实路由 AST 为 58/58 共享页面骨架；这表示结构迁移覆盖，不表示未运行的模型或外部基础设施操作已经验收。生产目标保持 ES2015，ID 校验不引入 BigInt 字面量
