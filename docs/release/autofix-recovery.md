# 自动修复操作恢复

工作流提交前为当前用户生成稳定操作 ID，并在当前标签页的会话存储中仅保存该 ID，不存储诊断正文或令牌。提交中断后不会自动重发；用户可以查询所属操作、待审批计划和授权范围内的历史。处理中或结果不确定时禁止重复执行，需人工核对；权限不足或状态读取失败明确显示原因。相同用户令牌刷新保留待核对 ID，不会解开在途提交锁；切换用户清除页面私有内容。

标签页关闭后，本地操作 ID 不再保留，可在具备相应 GET 权限时查询服务端历史。计划已存在但无法查询时按不确定处理。针对未见计划的 404，用户可以核对后使用同一 ID 手动重试；刷新后如没有保留原始正文，需要重新填写，服务端仍会检查同 ID 的请求摘要。

测试使用隔离 HTTP 替身和本地 Chrome，验证中断、刷新、待审批及不确定状态，未触发真实模型、通知或集群操作。项目现有 ESLint Unicorn 插件与当前 ESLint 版本存在兼容错误，本阶段类型检查、单元测试和构建各自验证，不将其称为完整 lint 通过。
