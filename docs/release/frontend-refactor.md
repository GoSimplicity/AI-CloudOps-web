# 前端全面重构验收口径

前一轮主题变量替换、编译和路由挂载检查没有证明完整重构。此后必须分别验收结构、视觉与业务行为，不能以“页面能打开”替代业务流程通过。

共享页面骨架位于 `apps/web-antd/src/components/ops/OpsPage.vue`，由应用自身维护，保留现有 Vben 与 Ant Design Vue。页面固定为标题与主操作、摘要、筛选、主体四个区域，摘要和筛选可按内容省略；业务表单、表格与事件仍在原页面。旧的页头/主操作样式在迁移时移除，避免各页继续自行覆盖。

`layout-inventory.json` 由 TypeScript AST 遍历已注册路由生成，避免把注释路由和未使用副本当成覆盖。`sharedPage` 只表示消费页面骨架，不代表视觉或功能已完成；终端、设计器等专用页面仍需适合任务的结构，不能机械套表格模板。

每个业务路由必须记录：

1. 实际注册的组件文件，消除同名副本与实际路由分离造成的漏改。
2. 页头、主操作、筛选、列表/详情、表单/抽屉、分页、空态、错误和加载反馈是否一致。
3. 浅色、深色、桌面与窄屏真实渲染；表单校验、键盘焦点及溢出。
4. 从真实界面触发查询、创建、编辑、取消、删除或该模块对应的完整业务动作，核对网络和持久化。没有数据源的能力明确标出，不能伪造数据或放行任意错误。

当前共享骨架覆盖用户、角色、API、审计、工单分类、告警规则、工单流程、模板、表单、Kubernetes 集群、命名空间、Deployment 与 Pod，共 13 个真实注册页面。旧清单中不存在的部门页面及未实际迁移的用户页面状态已纠正；实际路由数为 58。其余模块尚未完成，不据此宣布全站统一。

运行 `pnpm update:layout` 可从 TypeScript 路由 AST 和 Vue 模板 AST 再生成清单，`pnpm check:layout` 校验清单是否漂移；两者都在路由导入指向缺失文件时失败。该清单仅描述前端注册状态，不推断后端对应服务是否实现。
