# 第十三阶段：账户权限、路由与过期登录

日期：2026-10-23

## 变更日志

- 新登录和退出开始时同步清理权限码、菜单、权限检查状态、打开标签与动态路由，不等远程接口结束；静态登录及兜底路由保留
- 权限生成在异步数据返回、动态路由注册和菜单回填前验证 UID 与登录代际，迟到的旧权限成功或失败不影响新账户
- 过期弹窗重新登录后重新进入当前路由守卫；业务页面在当前账户权限检查完成后才允许挂载，防止新 UID 资料先返回时暂时渲染前账户匹配的路由
- 默认页面形式的过期登录策略保持既有配置，弹窗策略同样受账户边界保护

## 验证

先实证六个新失败场景，再完成修复：旧权限码/菜单保留、过期弹窗未重建权限、旧权限生成成功/失败回填、异步旧路由注册，以及权限未准备时旧路由组件过早挂载

五个相关文件共 29 项回归通过，其中异步注册测试使用真实 Vue Router，页面测试使用真实 RouterView/KeepAlive，另有真实应用请求 adapter 的跨账号回归。应用 TypeScript 通过

真实 Chrome 使用保存的偏好配置启用弹窗策略，控制注入一次列表 401 和刷新 401 后，确认旧业务内容卸载且登录弹窗可用；随后通过真实本地登录、资料与用户列表 API 200 恢复当前路由，2.5 秒通过。过期响应为受控注入，未声称服务器令牌自然到期；没有调用外部服务
